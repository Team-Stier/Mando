# Python 운영 클래스 한국어 docstring 설계

## 목적

SLAM 운영 Python 코드를 공부할 때 각 클래스의 책임과 처리 흐름을 클래스 선언부에서
바로 이해할 수 있도록, 주요 운영 클래스에 짧은 한국어 docstring을 추가한다.

## 대상

- `src/stier_slam_core/scripts/*.py`의 실행 노드 및 운영 클래스
- `src/stier_slam_core/src/stier_slam_core/*.py`의 핵심 로직, 지도 편집·배포 및
  runtime 보호 클래스
- 외부에서 직접 사용하는 데이터 클래스와 내부 동작을 이해하는 데 필요한 주요 내부
  클래스

테스트 클래스와 의미가 이름만으로 명확한 단순 예외 클래스는 제외한다.

## 작성 형식

각 클래스 선언 바로 아래의 docstring에 다음 두 항목을 작성한다.

```python
class VehicleOdometryNode:
    """역할:
    차량 속도와 조향각으로 wheel odometry를 생성한다.

    동작 방식:
    두 입력을 시간 기준으로 짝지어 Ackermann 모델로 위치를 적분하고,
    결과를 /slam/odometry/wheel 토픽으로 발행한다.
    """
```

- `역할`은 클래스가 담당하는 책임을 한두 문장으로 설명한다.
- `동작 방식`은 주요 입력, 핵심 처리, 출력을 한두 문장으로 설명한다.
- ROS 토픽, 메시지 타입, 클래스·함수·변수 이름은 기존 영어 표기를 유지한다.
- 기존 영어 docstring에 중요한 제약이 있으면 없애지 않고 한국어 설명에 포함한다.

## 비변경 조건

- 실행 로직, ROS 인터페이스, 설정값 및 예외 처리를 변경하지 않는다.
- 클래스·함수·변수 이름을 변경하지 않는다.
- 관련 없는 리팩터링이나 파일 이동을 하지 않는다.
- 사용자가 만든 미추적 architecture 파일을 수정하거나 커밋하지 않는다.

## 검증

- 변경 diff가 docstring에만 한정되는지 확인한다.
- `/usr/bin/python3 -m compileall`로 Python 문법을 검사한다.
- 기존 단위 테스트를 실행해 동작이 유지되는지 확인한다.
