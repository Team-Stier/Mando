Localization 코드 상세 설명

초기화 동작 변경: 이 페이지의 코드 스냅샷은 RDDF 동적 시작 위치 선택 기능 추가 전 버전입니다. 현재 시작 절차는 GPS/RViz 기반 RDDF 초기화 문서를 확인하세요. 저장된 소스 해시는 역사적 근거이며 현재 소스 일치 판정이 아닙니다.

현재 Mando Localization 소스의 처리 절차(3단계), 실패·복구·상태 판단(4단계), 파일·함수·줄 번호·SHA-256 근거(5단계)를 함께 기록했다. 기준: 2026-09-13 작업 시점의 파일. Git 저장소가 아닌 현재 workspace를 기준으로 하며 특정 main commit으로 표시하지 않는다.

설명은 한국어, ROS·함수 이름은 원문이다. Archify 고정 Viewer UI와 html lang은 지원 범위에 따라 영어로 표시된다.

정적 코드 확인: 아래 설명과 코드 링크. 설정: YAML/launch에 지정된 값. 이번에 하지 않은 검증: 실차·MORAI·rosbag 신규 실행 및 위치 정확도 측정. 기존 07번 재생 그림은 별도 산출물이며 이 문서의 실행 검증으로 취급하지 않는다.

읽을 때 구분할 동작

  • GPS 수신 중단은 source timeout → 다른 절대 소스 유무에 따라 DEGRADED 또는 제한된 DEAD_RECKONING으로 이어질 수 있다. invalid 입력이나 재연결 후보로 gate가 복구 신호를 켜면 RELOCALIZING이 우선한다.
  • replay.launch는 센서만 재생하고 LiDAR localization=false다. 범용 bringup.launch와 활성 소스 구성이 다르다.
  • Global Odometry는 추정 출력, /molit/localization/odometry는 별도 승인 출력이다. 출력 차단은 차량 제동 명령 발행과 다르다.
  • 엔코더 실측 보정은 unmeasured이고, 초기 RDDF heading은 GNSS heading 보정 완료나 실제 yaw 정확도 증거가 아니다.
  • 복구 그림의 GPS-only reset은 조건부 경로다. LiDAR 보조 승인에서는 reset 없이 reanchor로 이동한다. ACK와 timeout은 수신 이벤트·타이머의 대체 결과다.
  • 센서 그림의 엔코더와 IMU 경로는 별도로 실행된다. LiDAR와 두 EKF 그림에서 연결하지 않은 블록은 하나의 직렬 콜백이 아니다.
