# T870 보수적 조향 및 ROS 속도 제어 설계

## 목적

Arduino Uno 기반 BROON T870 하위 제어기에 측정된 조향 위치와 전륜
엔코더 정보를 반영한다. RC 모드의 직접 스로틀 조작은 유지하고 ROS
모드에서는 `DriveCmd.KPH`를 전륜 속도 목표로 사용한다. 첫 시험은 기어와
차량을 보호하는 저속·저출력 설정으로 제한한다.

## 확정된 측정값

- 전륜 엔코더: 바퀴 1회전당 300 software counts
- 타이어 지름: 약 270 mm
- 계산 원주: `pi * 0.270 = 0.84823 m`
- 조향 기계 끝: 왼쪽 ADC 999, 오른쪽 ADC 21
- 눈으로 맞춘 직진: ADC 약 640
- RC 배선과 보정값:
  - 조향 A0: 1100 / 1450 / 1800 us
  - 스로틀 A1: 1050 / 1450 / 1850 us
  - 모드 AUX A2: ROS 1200 us 이하, RC 1600 us 이상

지름으로 계산한 원주는 무부하 기하학값이다. 최종 속도 정확도는 차량을
바닥에서 한 바퀴 굴린 이동거리로 원주를 다시 보정한다.

## 조향 제어

조향은 P 제어를 사용한다. D항은 포텐시오미터 노이즈를 증폭할 수 있고,
I항은 기계 끝이나 백래시에서 계속 누적될 위험이 있어 초기 제어에서
사용하지 않는다.

- 기계 한계: 왼쪽 999, 오른쪽 21
- 안전 목표 범위: 왼쪽 850, 중앙 640, 오른쪽 170
- ADC는 오른쪽으로 조향할수록 감소한다.
- 최대 PWM: 45 / 255
- 최소 동작 PWM: 25 / 255
- 목표 데드밴드: 8 ADC
- P 이득 초기값: 0.25 PWM/ADC
- 안전 한계 접근 감속 구간: 100 ADC
- 안전 범위 밖 복귀 PWM 상한: 25 / 255

RC 조향은 최소값과 최대값을 한 번에 직선 보간하지 않는다. 1100~1450 us는
왼쪽 850에서 중앙 640으로, 1450~1800 us는 중앙 640에서 오른쪽 170으로
각각 보간한다. 따라서 조종기 중앙은 비대칭인 실제 직진 ADC 640을 목표로
한다. ROS의 -25~0~25도 역시 왼쪽 850~중앙 640~오른쪽 170으로 분할
보간한다.

조향 센서가 전기적 유효 범위를 벗어나거나, 명령 중 위치 변화가 없거나,
최대 연속 구동 시간을 넘으면 기존 래치 오류를 사용해 출력을 차단한다.

## ROS 속도 제어

ROS 모드의 `DriveCmd.KPH`는 PWM 요청이 아니라 전진 목표속도(km/h)다.
메시지 필드가 unsigned이므로 이 단계에서는 ROS 후진을 지원하지 않는다.
RC 모드는 기존의 스로틀-to-PWM 매핑을 유지한다.

속도 제어는 100 ms 엔코더 표본마다 PI 제어기로 계산한다.

- 최초 ROS 목표속도 상한: 3 km/h
- 최초 구동 PWM 상한: 80 / 255
- 목표속도는 급변하지 않도록 램프를 적용한다.
- P항은 현재 속도 오차에 반응한다.
- I항은 부하와 배터리 전압에 따른 잔류 오차를 천천히 제거한다.
- 출력 포화 중 같은 방향의 적분은 막아 적분 포화를 방지한다.
- 목표 0, brake, ROS timeout, RC 원격 정지, 모드 이탈 시 PWM과 적분을
  즉시 0으로 초기화한다.
- 동일한 제한 PWM을 전륜·후륜 구동 명령에 적용하고 기존 방향 전환
  인터록과 PWM 램프를 거친다.

지름 270 mm와 300 count/rev를 사용하면 1 count는 약 2.827 mm이며,
100 ms 표본에서 속도 해상도는 약 0.102 km/h/count다. 제어기는 이 양자화를
고려해 작은 오차에서 불필요하게 PWM을 흔들지 않도록 속도 데드밴드를 둔다.

## 속도 안전 감시

- 목표속도가 0보다 크고 구동 PWM이 감시 문턱 이상인데 1.5초 동안 전륜
  엔코더 변화가 없으면 구동 출력을 차단하고 오류를 래치한다.
- 측정속도가 허용된 절대 과속 한계를 넘으면 출력을 차단하고 오류를
  래치한다.
- 전륜 엔코더 방향이 뒤집혀도 속도 크기 제어는 가능하도록 전진 속도에는
  절댓값을 사용하되, 로그에는 signed count를 유지한다.
- 전륜 엔코더 하나만 사용하므로 센서가 없는 후륜의 개별 속도 차이는
  제어할 수 없다. 두 구동 모터는 같은 목표 PWM을 받는다.

## 데이터 흐름

1. RC 캡처와 ROS subscriber가 최신 명령을 갱신한다.
2. AUX와 원격 정지 조건으로 RC/ROS 모드와 명령 유효성을 판정한다.
3. 전륜 엔코더를 100 ms마다 속도(m/s, km/h)로 변환한다.
4. RC 모드에서는 스로틀을 제한 PWM으로 변환한다.
5. ROS 모드에서는 목표 KPH와 측정 KPH를 PI 제어기에 넣어 제한 PWM을 만든다.
6. 안전 상태, 방향 인터록, 출력 램프를 적용한 뒤 전륜·후륜에 출력한다.
7. 조향 P 제어는 같은 안전 상태 아래에서 별도로 실행한다.
8. ROS feedback과 사람용 로그에 목표속도, 측정속도, 속도제어 PWM,
   조향 목표/현재 ADC를 노출한다.

## 검증

- 순수 함수 단위 시험:
  - RC 조향의 1100/1450/1800 us가 850/640/170 ADC로 매핑되는지 확인
  - PI 출력 제한, 적분 포화 방지, reset, 속도 데드밴드 확인
  - 300 count와 0.84823 m로 계산한 속도 확인
  - 무피드백 및 과속 감시 상태 전이 확인
- Arduino Uno 기본 빌드와 ROS 활성 빌드를 모두 컴파일한다.
- 모터 출력 잠금 상태에서 센서·명령·계산 PWM 로그를 먼저 확인한다.
- 바퀴를 지면에서 띄우고 물리 전원 차단 수단을 준비한 상태에서 최대
  3 km/h, PWM 80 제한으로 최초 시험한다.
- 조향은 최대 PWM 45로 시작하고 움직이지 않을 때만 작은 단계로 상한을
  올린다. 안전 범위를 넓히거나 PWM을 높이는 변경은 최초 로그 검토 후에만
  수행한다.

## 출력 잠금 정책

코드에 보정값과 제어기를 구현하더라도 `BROON_ENABLE_ACTUATOR_OUTPUTS`와
`BROON_STEERING_CALIBRATION_CONFIRMED`는 검증 전까지 자동으로 켜지 않는다.
사용자가 벤치 조건을 준비하고 출력 활성화를 명시적으로 요청한 단계에서만
두 잠금을 변경한다.
