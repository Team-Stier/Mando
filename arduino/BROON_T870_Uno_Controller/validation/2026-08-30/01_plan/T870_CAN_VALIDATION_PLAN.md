# BROON T870 CAN 텔레메트리·자동진단 실차 검증 계획

## 1. 문서 정보

| 항목 | 내용 |
|---|---|
| 문서 버전 | 1.0 |
| 작성일 | 2026-08-29 KST |
| 계획 시험일 | 2026-08-30(변경 시 실행기록에 실제 날짜 기입) |
| 작성 상태 | 시험 전 기준선 |
| 대상 차량 | BROON T870 1대 |
| 대상 SW | Arduino Uno 하위제어기, CAN CSV 로거, Python 규칙 기반 진단기 |
| 작성자 | 시험 전 기입 |
| 검토자 | 시험 전 기입 |

이 문서는 시험 결과를 본 뒤 합격 기준을 맞추기 위해 소급 작성하지 않는다. 변경이
필요하면 기존 내용을 삭제하지 않고 문서 버전과 변경 이유를 남긴다.

## 2. 목적

1. RC 및 ROS 주행 중 하위제어기 상태가 CAN을 통해 손실 없이 기록되는지 확인한다.
2. 정상 주행에서 기존 규칙이 고장을 잘못 검출하는 오탐을 측정한다.
3. 안전하게 재현 가능한 신호 손실에서 예상 상태와 진단 이벤트가 발생하는지 확인한다.
4. 최초 임계값을 수정할 경우 전체 로그 회귀시험으로 다른 판정이 손상되지 않았는지
   확인한다.
5. 요구사항, Test Case, 원본 로그, 분석 결과와 최종 판정의 추적성을 확보한다.

## 3. 검증 범위와 제외 범위

### 포함

- RC/ROS 모드, 제어기 state·fault·안전 flag
- 요청·전륜·후륜 PWM
- 목표·실제 조향 ADC와 조향 PWM
- 전륜 엔코더 delta와 계산 속도
- RC 조향·스로틀·AUX 펄스 및 유효 flag
- CAN complete, sequence, drop, EFLG, TEC, REC
- CSV 자동 저장과 규칙 기반 진단보고서 생성

### 제외 및 한계

- 후륜 엔코더가 없으므로 후륜 단독 고장을 확정하지 않는다.
- 배터리 전압, 모터 전류·온도, 도어, 기어, 시동과 인포테인먼트 신호는 수집하지 않는다.
- CAN CSV의 완전 샘플 주기는 약 120 ms이므로 RC 정지시간 100 ms 요구를 정밀하게
  입증할 수 없다. 필요하면 오실로스코프 또는 로직 애널라이저로 별도 측정한다.
- Arduino에는 ROS 명령 1초 timeout 안전 로직이 있지만 Python 진단기에 독립적인
  `ROS_COMMAND_TIMEOUT` 이벤트는 없다. SAFE-02는 하위제어기 상태전이 시험이다.
- 실제 부품 고장을 확정하지 않고 로그가 지시하는 우선 점검 후보만 보고한다.
- 조향기어 고정, 주행 중 엔코더 탈거 등 위험한 고장 주입은 수행하지 않는다.

## 4. 시험 구성

```text
RC 송신기 또는 ROS 상위제어
             |
       제어 Uno(A)
             |
      MCP2515/TJA1050
             |  CAN 500 kbit/s, 8 MHz
      MCP2515/TJA1050
             |
       로거 Uno(B)
             |  USB 115200 baud
          Ubuntu
             |
        원본 CSV + 진단보고서
```

CAN-H와 CAN-L 양 끝에는 120 ohm 종단저항을 각각 하나씩 두며, 전원 차단 상태의
CAN-H/L 합성저항 약 60 ohm을 확인한다. 두 모듈과 Uno에는 24 V를 직접 연결하지
않는다.

## 6. 빌드 설정

| 단계 | ACTUATOR | ROS | HUMAN_SERIAL | CAN | 목적 |
|---|---:|---:|---:|---:|---|
| CAN-01 | 0 | 0 | 1 | 1 | 모터 전원 차단 기본 통신 |
| RC 시험 | 1 | 0 | 1 | 1 | RC 저속 주행 및 신호 손실 |
| ROS 시험 | 1 | 1 | 0 | 1 | ROS 저속 주행 및 명령 중단 |

각 행은 `BuildOptions.h`의 `BROON_ENABLE_*` 값이다. 액추에이터 출력 `1`은 기존
RC·ROS 검증과 교정이 유효하고 리프트 휠 재확인이 끝난 경우에만 사용한다.

## 7. 요구사항과 합격 기준

| 요구사항 ID | 요구사항 | 합격 기준 |
|---|---|---|
| REQ-CAN-01 | 정상 버스에서 완전한 텔레메트리를 수신해야 한다. | 30초 구간 `protocol=1`, complete 비율 99% 이상, EFLG=0, TEC/REC<32, tx_dropped 지속 증가 없음 |
| REQ-CAN-02 | CAN 모니터링 고장이 차량 제어 허가를 변경하면 안 된다. | 모터 전원 차단 조건의 CAN 분리 전후 의도하지 않은 출력·상태 해제 없음 |
| REQ-RC-01 | 정상 RC 주행을 이상으로 판정하면 안 된다. | 사전 정의한 정상 구간에서 예상하지 않은 MEDIUM/HIGH 이벤트 0건 |
| REQ-ROS-01 | 정상 ROS 주행을 이상으로 판정하면 안 된다. | 사전 정의한 정상 구간에서 예상하지 않은 MEDIUM/HIGH 이벤트 0건 |
| REQ-DRV-01 | 구동 명령에는 전륜 피드백이 따라야 한다. | PWM 60 이상 구간에서 1.5초 지속 `DRIVE_NO_FEEDBACK` 없음 |
| REQ-DRV-02 | 측정속도는 현재 ROS 측정속도 제한 이하여야 한다. | ROS 정상 시험에서 `speed_kph` 절댓값 15.0 이하 |
| REQ-STR-01 | 조향 명령에는 센서 응답이 따라야 한다. | 정상 조향에서 추종오차·무응답·헌팅 이벤트 없음, 기계 끝 접촉 없음 |
| REQ-SAFE-01 | RC 신호 손실 시 출력을 허용하면 안 된다. | RC invalid 기록, DISARMED 또는 즉시정지, 구동·조향 출력 0 |
| REQ-SAFE-02 | ROS 명령 1초 timeout 후 출력을 허용하면 안 된다. | 마지막 명령 후 1.0초+최대 2개 CAN 완전 샘플 이내 DISARMED 및 출력 0 |
| REQ-REG-01 | 규칙 수정이 기존 정상 판정을 손상하면 안 된다. | 모든 원본 로그 재분석 후 기존 PASS 유지, 새 오탐 0건 |

REQ-CAN-01의 99%는 짧은 최초 통합시험의 임시 데이터 품질 기준이며 법규나 양산
요구사항이 아니다. 최초 실측 후 기준을 바꾸면 전후값과 근거를 최종 보고서에 남긴다.

## 8. Test Case

### TC-CAN-01 기본 CAN 통신

- 사전조건: 모터 24 V 차단, 바퀴 리프트, CAN 설정 행 적용
- 절차: 두 Uno 전원 인가 후 30초 이상 CSV 저장
- 관찰값: complete, seq, protocol, tx_dropped, EFLG, TEC, REC
- 기대결과: REQ-CAN-01 충족
- 원본 파일명: `t870_can_poweroff_01.csv`

### TC-RC-01 RC 정차 정상

- 사전조건: RC 모드, 정상 수신기, 중립 명령
- 절차: 20초 이상 정차 상태 저장
- 관찰값: state, fault, RC pulse/flags, PWM, speed, 진단 이벤트
- 기대결과: 구동·조향 PWM 0, 속도 0 부근, 예상하지 않은 MEDIUM/HIGH 이벤트 0건
- 원본 파일명: `t870_rc_stationary_01.csv`

### TC-RC-02 RC 저속 직진·가감속

- 사전조건: 리프트 휠 선행 PASS 후 폐쇄구역·무인·무하중 저속 시험
- 절차: 정지 20초 → 저속 직진 30초 → 감속·정지 20초
- 관찰값: 요청/전륜/후륜 PWM, speed, encoder_delta, drive 이벤트
- 기대결과: 명령 구간 속도·엔코더 응답, 과속·무응답·PWM 불일치 이벤트 없음
- 원본 파일명: `t870_rc_drive_01.csv`

### TC-RC-03 RC 좌·우 조향

- 사전조건: 저속 또는 리프트 상태, 기계 끝에서 충분히 떨어진 범위
- 절차: 중앙 10초 → 완만한 좌조향 10초 → 중앙 10초 → 우조향 10초 → 중앙
- 관찰값: steer_target_adc, steer_actual_adc, steer_pwm, 조향 이벤트
- 기대결과: 실제 ADC가 목표 방향으로 변하고 추종오차·무응답·헌팅 이벤트 없음
- 원본 파일명: `t870_rc_steering_01.csv`

### TC-ROS-01 ROS 저속 직진·정지

- 사전조건: ROS 모드, rosserial 연결, 유효한 RC AUX, ROS 설정 행 적용
- 절차: KPH 0을 20초 → KPH 1을 30초 → KPH 0을 20초
- 관찰값: mode, state, drive PWM, speed, encoder_delta, drive 이벤트
- 기대결과: 목표속도 구간의 피드백 발생, 정지 후 출력 0, 예상하지 않은 이벤트 없음
- 원본 파일명: `t870_ros_drive_01.csv`

### TC-ROS-02 ROS 좌·우 조향

- 사전조건: 리프트 또는 폐쇄구역 저속, 기계 끝을 피한 목표각
- 절차: Deg 0 → +10 → 0 → -10 → 0을 각 10초 이상 유지
- 관찰값: steer target/actual/PWM, fault, 조향 이벤트
- 기대결과: 목표 방향의 센서 응답, 조향 fault와 예상하지 않은 진단 이벤트 없음
- 원본 파일명: `t870_ros_steering_01.csv`

### TC-SAFE-01 RC 수신기 신호 손실

- 사전조건: 바퀴 리프트, 즉시 24 V 차단 가능, 저출력 또는 중립
- 절차: 정상 수신 10초 후 수신기 전원 차단, 5초 후 시험 종료
- 관찰값: rc_flags, state, status_flags, 모든 PWM, `RC_SIGNAL_INVALID`
- 기대결과: RC invalid와 출력 차단. CAN 로그만으로 100 ms 정밀시간은 판정하지 않음
- 원본 파일명: `t870_rc_loss_01.csv`

### TC-SAFE-02 ROS 명령 timeout

- 사전조건: 바퀴 리프트, ROS 모드, KPH 1 저출력 명령
- 절차: 정상 명령 10초 후 `/drive` 발행 중단, 5초간 상태 저장
- 관찰값: mode, state, status_flags, drive PWM, speed
- 기대결과: REQ-SAFE-02 충족. Python 독립 ROS timeout 이벤트는 기대하지 않음
- 원본 파일명: `t870_ros_timeout_01.csv`

### TC-CAN-02 CAN 모니터링 고장 분리

- 사전조건: 모터 24 V 차단, RC 모드, 사람용 Serial 사용 가능
- 절차: 정상 CAN 10초 → 로거 전원 차단 또는 버스 분리 → 10초 관찰 → 안전 정지 후 복구
- 관찰값: 제어 상태, 의도하지 않은 출력, 복구 후 drop/TEC/EFLG
- 기대결과: CAN 고장만으로 출력이 새로 허가되거나 안전정지가 해제되지 않음
- 원본 파일명: 연결 구간 `t870_can_disconnect_01.csv`; 무수신 구간은 현장기록·영상으로 보완

## 9. 현장 기록 규칙

- 각 상태 변경의 실제 KST 시각을 실행기록에 남긴다.
- 원본 파일명은 계획과 다르면 실행기록에 실제 파일명을 적는다.
- 예상하지 않은 동작은 시험을 즉시 중단하고 24 V를 차단한다.
- 오탐은 실제 정상인데 진단 이벤트가 발생한 경우로 정의한다.
- 미탐은 계획에서 기대한 이벤트가 유효 로그에 발생하지 않은 경우로 정의한다.
- 데이터가 없거나 complete=0 구간은 PASS가 아니라 판정불가로 처리한다.

## 10. 분석·수정·회귀 절차

1. 모든 원본 CSV의 SHA-256 해시를 생성한다.
2. 최초 `thresholds_before.json`으로 모든 로그를 분석한다.
3. 현장기록과 이벤트를 대조해 TP, FP, FN, TN 또는 판정불가로 분류한다.
4. 오탐·미탐이 있을 때 물리적 근거가 확인된 규칙만 수정한다.
5. 수정 전후 임계값, 변경 이유와 영향을 기록한다.
6. 같은 원본 로그 전체를 수정 후 규칙으로 다시 분석한다.
7. 기존 PASS 유지와 새 오탐 0건을 확인한다.
8. 최종 보고서에 미해결 한계와 후속시험을 기록한다.

## 11. 정량 지표

| 지표 | 계산식 |
|---|---|
| 총 시험시간 | 각 원본 로그 시간 합계 |
| 총 샘플 수 | 유효 CSV 데이터 행 수 |
| 완전 샘플 비율 | complete=1 행 / 전체 행 × 100 |
| Test Case 통과율 | PASS 수 / 실행한 판정 가능 TC 수 × 100 |
| 정상 오탐률 | 정상 구간 FP 이벤트 수 / 정상 주행시간(분) |
| 이상 검출률 | TP / (TP+FN) × 100 |
| 검출 지연 | 실제 이상 시작시각부터 첫 관련 이벤트시각까지 |
| 오탐 감소율 | (수정 전 FP-수정 후 FP) / 수정 전 FP × 100 |
| 회귀 통과율 | 수정 후 기존 PASS 유지 TC / 기존 PASS TC × 100 |

분모가 0인 지표는 0%로 만들지 않고 `N/A`로 기록한다. 합성 로그 결과와 실차
로그 결과는 별도 항목으로 구분한다.
